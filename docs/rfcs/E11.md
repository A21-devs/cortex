# RFC E11: shell and design system

Owner: E11. Each item is a request to the architect or to the named owner. E11 uses a local adapter meanwhile, so nothing here blocks the build.

## 1. Stage events the shell and the renderer exchange (state/events.ts, architect)

What: `ui/context.ts` declares `StageEvents` (`stage:layout`, `stage:camera`, `stage:territories`, `stage:labels`, `stage:arrangement`, `stage:status`, `stage:restart`, `stage:turn`, `toast`) and types them through `stageBus(bus)`. They ride the shared `EventBus` under their own names.

Why: the frozen `CortexEvents` map does not carry them. `ui/mount.tsx` (`bindShell`) emits `stage:layout` and consumes the renderer's events into `Shell.feed`.

```ts
// state/events.ts, add to the event map (payloads exactly as ui/context.ts StageEvents)
"stage:layout": { viewId: string; width: number; height: number; insetRight: number; overlays: StageRect[]; safe: StageRect; fit?: "figure" | "brain" };
```

`fit` is new: `"brain"` in the Mini breakpoint (CORTEX-UX §2.5: the brain only, fitted to its crown and cerebellum, inside `safe`), `"figure"` otherwise. E10 reads it in `applySize()`; until it does, Mini shows the whole figure small.

## 2. Default pose is Standing (shared/settings.ts, state/types.ts, architect; CORTEX-UX §12.19 item 1)

What: `DEFAULT_SETTINGS.general.pose` is still `"lying"` and `defaultView()` falls back to `settings?.general.pose ?? "lying"`.

Why: the shell never hard-codes a pose. It reads `store.get("view").pose`, which `defaultView(settings)` seeds. The shell's tests set the pose explicitly, so they pass either way; with the old defaults a fresh leaf opens Lying.

```ts
// shared/settings.ts: DEFAULT_SETTINGS.general.pose = "standing"; general.poseChosen: boolean = false; bump SETTINGS_VERSION and migrate
// state/types.ts line 87
const pose = settings?.general.pose ?? "standing";
```

## 3. The motion command id (plugin/commands.ts, plugin/commandRun.ts, E1; CORTEX-UX §12.19 item 3)

What: rename `toggle-drift` to `toggle-motion`, name "Spin on or off".

Why: the Space key and the tool column use the id `toggle-motion` (`ui/keymap.ts`, `ToolColumn.tsx` tool `"motion"`). `keymap.ts` still accepts E1's `toggle-drift` so the palette command works until the rename lands; `KeyAction` includes `"toggle-motion"` locally.

## 4. A period preview in the renderer (render/controller.ts, E10)

What: the time strip sets `ui.preview = { kind: "period", key: "<startMs>-<endMs>" }` while a bar is hovered; `controller.ts` only honours `kind: "area"`.

Why: CORTEX-UX §5.8 "the brain previews that week (matches full, others at 35%)". The renderer should light the points whose `cols.t` lies in `[start, end)` and drop the rest to the preview-others alpha.

## 5. Label anchor keys for the cord (render/overlay.ts, E10; CORTEX-UX §6.11)

What: `stage:labels` anchors for cord segment names ("T4") use keys starting `cord:` or `segment:`; `LabelLayer` places those beside the cord, and all other chips in the two columns either side of the brain (outside the torso below it).

Why: `LabelLayer.layoutLabels(…, columns)` needs to tell a segment name from a note chip without a new field.

## 6. Copy keys (ui/copy.ts, E12)

What: add `tools.spin` ("Spin") next to `tools.drift`; `ToolColumn` currently builds the tool name from `display.spin` / `display.drift` by pose, so nothing breaks until then. The strings in `PENDING_COPY` (`ui/context.ts`) move to `COPY.shell.*` as before.

## 7. Leaf commands without a subscriber (E10, E7)

What: `save-image` and `copy-data-csv` are published on the bus (`command` event) by the palette and the More menu; `toggle-sample` has no service to flip the sample record.

Why: E10 owns the picture and CSV export, E7 the sample record. The shell only publishes them.
