# RFC E10: renderer

Owner: E10. Each item is a request to the named owner. The renderer works without any of them: it reads the pose from the leaf's view state, looks haze kinds up by name, and ships local adapters where noted.

## 1. Default pose in settings and view state (architect: `shared/settings.ts`, `state/types.ts`)

What: CORTEX-UX §12.1 as specified. The renderer takes the pose from `ViewControls.pose` (`CortexRenderer.setView`) and, for a camera built with no pose, from `DEFAULT_SETTINGS.general.pose`; nothing in `src/render` hard-codes a pose. Until the defaults change, a fresh leaf is Lying.

Why: Standing is the default pose; `DEFAULT_SETTINGS.general.pose` is still `"lying"` and `defaultView()` falls back to `"lying"`.

```ts
// shared/settings.ts
general: { pose: Pose; /** false until the person picks a pose; a stored "lying" from an older build reads as Standing. */ poseChosen: boolean; ... }
DEFAULT_SETTINGS.general.pose = "standing";
DEFAULT_SETTINGS.general.poseChosen = false;
// bump SETTINGS_VERSION; migration: if (!poseChosen) pose = "standing"

// state/types.ts, defaultView()
const pose = settings?.general.pose ?? "standing";
```

## 2. Haze kinds (architect: `shared/protocol/worker.ts`; E8: `worker/anatomy.ts`)

What: replace the filled-body haze with the nerve haze (§12.6). The renderer indexes per-kind intensity, brain colouring and the birth flash by kind NAME (`layers/haze.ts`: `hazeIntensityOf`, `isBrainKind`, `flashesOnBirth`; up to `HAZE_SLOTS` = 12 kinds), so the list can change without a renderer change.

```ts
export type HazeKind = "brain" | "nerve" | "thread" | "ring" | "brainstem" | "undated";
export const HAZE_KINDS: readonly HazeKind[] = ["brain", "nerve", "thread", "ring", "brainstem", "undated"];
// optional finer brain kinds are also understood: "brainFolds" | "brainVolume" | "brainLips" | "cerebellum"
```

Known gap: the nerve guides' 0.24 → 0.13 gradient along a guide needs a per-point parameter. The haze layer has one intensity per kind (`intensity.haze.nerve` = 0.18, the mean of the guides and twigs). If the worker writes the guide parameter u (0 at the cord, 1 at the end) into `PlacementResult.haze.birth`'s fractional part or a new `haze.along: Float32Array`, the shader can apply the gradient; ask only if the flat value looks wrong against main.png.

## 3. Source lines are chords (E8: `worker/lines.ts`)

What: for the `source` family the worker returns ONE straight segment per line, note → entry (`positions` = the note then the entry, `t` per vertex in that order, e.g. 1 then 0 so the line draws on from the entry), `owner` = the note, `target` = the entry. The renderer turns each chord into a quadratic curve whose control point is level with the chord's middle, on the entry's side of the cord, at 2 × w(y) + 0.2 from the axis (§6.10, §12.7: `layers/lines.ts` `routeSourceLines`, `envelopeHalfWidth`), with 4 to 16 pieces per line so the 60,000-segment budget holds. Stems and spokes stay as sent.

Why: the curve has to clear the torso envelope, which is the renderer's `RENDER_TUNING.figure.envelope` (the §6.2 table); the worker does not need to know it.

## 4. Hover on a line (architect: `state/types.ts`)

What: `HoverState` has only an ordinal, so hovering a source line currently reports its NOTE as the hovered item at the pointer. The tooltip copy `tipLineOf` ("{title} → 1 of its {n} sources") needs the family:

```ts
export interface HoverState {
  ordinal: number;
  x: number;
  y: number;
  /** Set when the pointer is on a line, not a point: the line family and the far end's ordinal. */
  line?: { family: "source" | "stem" | "spoke"; target: number };
}
```

The controller will fill `line` as soon as the field exists (`render/controller.ts` `lineHover`).

## 5. Label columns (E11: `ui/stage/LabelLayer.tsx`)

What: the standing figure's chips go in two columns beside the brain (§6.11). `render/overlay.ts` now exports `layoutChips(chips, bounds, blockers, columns?)` and `labelColumnsFor(brainLeftPx, brainRightPx)`. `LabelLayer` can call them instead of its own placement, or keep its own: the renderer's `stage:labels` anchors are unchanged.

## 6. Renderer API added (for E11, no action needed)

`CortexRenderer` gained `setPose`, `setStage`, `setHazeColours`, `setDimming`, `setScopeSink`, `turnTo`, `setHover`, `setSelected`, `setActive`, `setRingColours`, `setPointBudget`, `bornNow`, `setMaxFps`, `renderPixels`, `figureBounds`, `home`, and `setPlacement(p, count, look)` now takes the per-ordinal `PointLook` (`render/controller.ts` `buildLook`). `RenderController` gained `home()` and `savePicture()` (PNG bytes at 2×, overlays included); `command` event `save-image` can call `controller.savePicture()` and hand the bytes to `plugin/saveFile.ts`.
