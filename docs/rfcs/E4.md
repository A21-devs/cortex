# RFC E4: export importers (Claude.ai, ChatGPT, Gemini) and import.inspect

Owner: E4. Each item is a request to the architect or to the named owner. E4 uses a local adapter meanwhile, so nothing here blocks the build.

## 1. A batch type that carries what exports need (importers/common.ts, E3)

What: E3's `ConversationBatch` (the writer's input) has no place for kept-branch versions, attachment references, document entries inside a conversation, entries outside any conversation (Claude.ai project documents), replacement of an earlier entry, or per-turn date strength. E4 therefore ships its own writer, `ExportWriter` in `importers/zip.ts`, fed by `ExportConversation` / `ExportTurn`.

Why: ChatGPT regenerations and edits are `BranchVersion`s of one entry; Claude.ai attachments are `document` entries beside their message; project documents have no conversation. None of these fit `PendingMessage[]`.

Exact (already in `zip.ts`, proposed to move to `common.ts` so E3 and E4 share one writer):

```ts
export interface ExportTurn {
  nativeId: string;
  key: string;                       // entryId(source, key)
  kind: "message" | "document";
  speaker: Speaker;
  speakerDetail?: string;
  title?: string;                    // documents
  text: string;
  at?: IsoDate;
  atStrength?: DateStrength;         // default "strong"; documents default "bound"
  atDetail?: string;
  hidden?: EntryRecord["hiddenByDefault"];
  attachments?: AttachmentRef[];     // listed, never stored (text only by default)
  versions?: { nativeId: string; key: string; text: string; at?: IsoDate }[];
  unitSha256: string;
}
```

Until then E3's importers are untouched.

## 2. Stats and warnings for export passes (shared/protocol/runner.ts, architect)

What: `ExportImportStats extends SourceImportStats` with three counters, and one new warning code.

```ts
export interface ExportImportStats extends SourceImportStats {
  secretsHeld: number;   // secrets replaced by SECRET_MARKER in the vault copy (kept in <cache>/held/)
  partial: boolean;      // the pass stopped early (deadline, pause, limit, cancel, damaged file): run again to continue
  excluded: number;      // conversations left out by the person's exclusions
}
// WarningCode: add
| "export-truncated"
```

Why: a download that was cut off still yields every complete conversation. Today the pass imports them, ends with `partial: true`, stores `status: "error"` in `sources.json` and reports `E_PARSE` in `errors`. `export-truncated` would let Add sources say "This export looks cut off. Cortex imported what it could; download it again to get the rest." instead of a generic failure.

## 3. `InspectResult` additions (shared/protocol/runner.ts, architect)

What: two optional fields so the preview can tell the person more without reading text.

```ts
export interface InspectResult {
  // …existing…
  /** The file ends before its list does; `conversations` counts the complete ones. */
  truncated?: boolean;
  /** Gemini only: exchanges that were left out because they are not prompts (feedback lines, "Used Gemini Apps"). */
  skippedActivity?: number;
}
```

Why: the Gemini row already shows a grouping note; a cut-off export is the most common support case for multi-GB downloads. E4 does not set them until they exist.

## 4. Gemini Takeout in HTML (CORTEX-UX §5.26, copy)

What: HTML is recognised and refused with `takeout-html` ("Choose JSON when you export from Google Takeout"). No change requested; recorded here because the user brief lists HTML. The HTML file writes dates in the viewer's language and time zone ("Jan 5, 2026, 3:04:05 PM PST"), so reading them back would put entries on wrong days, which the record must never do.
