# RFC E2: record store

Owner: E2. Each item is a request to the named owner. E2 keeps working meanwhile, so nothing here blocks the build.

## 1. Pass the vault to the LedgerService (plugin/container.ts, E1)

What: `createLedgerReader` now needs the vault and cache folders to read the ledgers. Called with no argument (as `container.ts` does today) it still type-checks, and every method rejects with `E_INTERNAL` ("LedgerService was created without a vault folder"), so Agents, Checks and the Access log show an error until this is wired.

Why: the service is read-only over `.vault-meta/cortex/**` and keeps its aggregates in `<cache>/agg/`.

```ts
// container.ts, where `ledger: createLedgerReader()` is built
ledger: createLedgerReader({ vaultRoot: bg.vaultRoot, cacheDir: bg.cacheDir, log: bg.log.child("ledger") }),
```

Call `bg.ledger.invalidate()` on a cache signal that lists `runs`, `reads`, `review`, `receipts`, `labels` or `corrections` (the aggregates also carry a file signature, so a missed call never serves stale data).

## 2. Summary template: block id before or after the footnote (CORTEX-UX §5.15, architect)

What: the §5.15 sample shows `- question: text ^n-4f2a [^1]`. Obsidian only registers a block id at the end of a line, so `notesWriter` writes `- question: text [^1] ^n-4f2a`. Everything else in the template matches.

Why: block references (`[[note#^n-4f2a]]`) fail when the id is not last.

Proposed: change the sample in §5.15 to `text [^1] ^n-4f2a`.
