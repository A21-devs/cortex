# RFC E7: index, search and state

Owner: E7. Each item is a request to the named owner. E7 works without any of them: the services below are built from optional dependencies (like E3's), so the container keeps compiling and an unconnected service answers `E_INTERNAL` ("... is not connected to the vault") instead of guessing.

## 1. Connect the three services (plugin/container.ts, E1)

What: `createIndexService`, `createCorrectionService` and the sample record controller now take their dependencies. The disk-backed variants live in two new E7 files, `plugin/indexerNode.ts` (`createNodeIndexService`) and `plugin/correctionsNode.ts` (`createNodeCorrectionService`), because `plugin/indexer.ts` and `plugin/corrections.ts` are imported (types only) by the UI, and the browser typecheck (`tsconfig.browser.json`, `types: []`) must not reach Node modules through them. Keep importing the implementations only from the container.

```ts
// container.ts, inside createServices (the ledger store and store context are the runner-free ones the plugin already opens)
const storeCtx = await openStoreContext({ vaultRoot: bg.vaultRoot, cacheDir: bg.cacheDir, owner: "plugin", log: bg.log.child("store") });
const ledgerStore = createLedgerStore(storeCtx);

const corrections = createNodeCorrectionService({
  ctx: storeCtx, ledger: ledgerStore,
  settings: bg.settings,                       // SettingsHandle: only `update` and `value` are used
  sandbox: () => sandbox.peek(),
  log: bg.log.child("corrections"),
  applyTheirs: async (card) => {                // "Use theirs" on a conflict check (CheckAnswer { kind: "conflict", keep: "theirs" })
    const p = card.proposal as ConflictCardProposal;
    await writeDerivedNote(storeCtx, { path: p.path, markdown: p.markdown, ownedSha256: ownedHash(p.markdown) }, undefined, { overwriteUserEdits: true });
  },
});
void corrections.load();                        // list() is empty until this resolves; RecordReader reads it through `corrections.list()`

const index = createNodeIndexService({
  app: bg.app, vaultRoot: bg.vaultRoot, cacheDir: bg.cacheDir, owner: "plugin", settings: bg.settings,
  log: bg.log.child("index"), bus: bg.bus, shared: bg.shared, runner: bg.runner, worker, corrections,
});

const sampleRecord = createSampleRecord({ index, sandbox, setSandbox: (on) => setSandbox(built, on) });   // enter() / leave() / toggle()
```

Also: call `index.load()` from the first view open and from the background tier after the first import; `corrections.refresh()` is called by the index service on the `corrections` signal, so nothing else needs to. The `toggle-sample` leaf command (E1 `commandRun.ts`) should call `sampleRecord.toggle()`.

Why: SERVICES-CONTRACT-GAPS; `RecordReader` already takes `corrections: () => corrections.list()` and `index: () => index.index.peek()`.

## 2. `command` event is declared (state/events.ts, E1)

What: `state/events.ts` is E7's file and now declares `command: { viewId; id: "save-image" | "copy-data-csv" | "toggle-sample" }`, `arrivals: { added; available }` and `warning: { code; detail? }`. E1's `emitLeafCommand` / `onLeafCommand` can become plain `bus.emit("command", ev)` / `bus.on("command", fn)` (see RFC E1 §1).

## 3. Cache housekeeping (store/layout.ts, E2)

What: `CLEARABLE_CACHE_FILES` should also name `vault.cxi.key` (the key of the cached vault part, written beside `vault.cxi`) and the files under `search/` (`*.cxs` and `vault.sig`). "Clear local cache" then leaves nothing that could pair a stale key with a rebuilt file. The readers already tolerate a missing key (they rebuild).

```ts
export const CLEARABLE_CACHE_FILES: readonly string[] = [..., "vault.cxi.key"];
// plus: every `*.cxs` and `vault.sig` directly inside `search/`
```

## 4. One corrections fold (agents/jobs.ts E6, importers/common.ts E3; optional)

What: `shared/correctionsFold.ts` (E7, pure) is now the single fold: `foldCorrections`, `undoneIds`, `nextVersion`, and `exclusionMatcher` (one rule for the five exclude scopes). `agents/jobs.ts` and `importers/common.ts` (`foldExclusions`) each carry a copy of the undo walk; they can import these instead so the index builder, the importers and the jobs can never disagree about what is excluded. Nothing breaks if they keep their copies: the rules are the same.

## 5. How the Checks Z key and the check tags work (ui/pages/Checks.tsx, E12)

What: `CorrectionService.resolveCheck(cardId, answer)` returns the record that marks the card answered (the record whose `target` is the card id) or `null` for Skip. Every record of one answer carries `reason: "check:<card id>:<answer kind>[:detail]"`. Z should call `corrections.undo(<that record's id>, "checks")`; the service then undoes every record of the answer together (a Change on a label card writes several set-label / confirm records). `LedgerService.checks` keeps working unchanged because it treats a card as open until a standing correction targets it.

## 6. Sample record text (store/recordReader.ts E2, ui/reader E12)

What: while `sandbox` is true the readers should answer with `sampleTextResult(ordinal)` from `plugin/sampleRecord.ts` (`{ ok: true, text, version: 1 }`, deterministic made-up sentences) instead of `{ ok: false, reason: "sample" }`, so the tour of the sample record is readable. Writes keep refusing with `assertNotSample(() => sandbox)` ("Not available in the sample record.").
