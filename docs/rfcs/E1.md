# RFC E1: platform and kernel

Owner: E1. Each item is a request to the architect or to the named owner. E1 uses a local adapter meanwhile, so nothing here blocks the build.

## 1. A `command` event on the bus (state/events.ts, architect)

What: leaf-UI commands (Save image, Copy data as CSV, sample record toggle) have no state action; the palette command has to reach the owning leaf UI.

Why: `plugin/commandRun.ts` publishes them on the bus today through a local cast (`emitLeafCommand`, `onLeafCommand`, event name `"command"`). E10 / E11 subscribe with `onLeafCommand(bus, fn)` and act when `viewId` is theirs.

```ts
// state/events.ts, add to the event map
command: { viewId: string; id: "save-image" | "copy-data-csv" | "toggle-sample" };
```

Once declared, `emitLeafCommand` / `onLeafCommand` become plain `bus.emit("command", ev)` / `bus.on("command", fn)`.

## 2. `useDefaults` on the settings handle (plugin/services.ts, architect)

What: the corrupt-settings screen (SAFE-08) needs to replace unreadable settings with the defaults.

Why: `settingsStore.ts` already provides it on `CortexSettingsHandle`. E12's settings tab narrows with `"useDefaults" in handle`; moving it into `SettingsHandle` removes the cast.

```ts
export interface SettingsHandle {
  // ...existing members
  /** Replace unreadable settings with the defaults; keeps `.data.json.unreadable` first. No-op when not corrupt. */
  useDefaults(): Promise<void>;
}
```

## 3. Copy for the status bar and notices (ui/copy.ts, E12)

`plugin/statusBar.ts` and `plugin/notices.ts` carry fall-back strings and use the catalogue when a key exists. Please add (names are the keys looked up):

```ts
statusBar: {
  settings: "Cortex · check settings",
  importingNoTotal: "Cortex · importing",
  indexingNoTotal: "Cortex · indexing",
  limit: "Cortex · usage limit reached",
  unsafe: "Cortex · agents off",
  off: "Cortex · agents off",
},
notices: {
  failed: "Cortex couldn't finish that. Nothing was changed.",
  busy: "Cortex is busy with another task. Try again in a moment.",
  notFound: "Cortex couldn't find that in your record.",
},
```

`noticeText(key)` in `plugin/notices.ts` would then read `t("notices.<key>")`.

## 4. Factory dependencies for the UI-tier services (container wiring, E2 / E6 / E7 / E8 / E12)

`plugin/container.ts` `createServices` calls the factories with these arguments today:

| Factory | Called with |
|---|---|
| `createRecordReader` | `{ vaultRoot, cacheDir, index: () => index.index.peek(), corrections: () => corrections.list(), sandbox: () => sandbox.peek(), log }` (wired) |
| `createWorkerClient` | `log` |
| `createRendererPool` | defaults |
| `createIndexService`, `createCorrectionService`, `createAssistantExecutor`, `createColourSlotService`, `createSourcesService`, `createNewEntryService` | no arguments (architect skeletons) |

When an owner gives its factory real dependencies, it files an RFC here with the exact `Deps` type. E1 then wires them from `BackgroundServices` (`app`, `vaultRoot`, `vaultKey`, `cacheDir`, `settings`, `bus`, `log`, `shared`, `runner`, `notices`, `ledger`), the runner client being the only route to the vault writer.

## 5. Nothing else

No new npm dependencies. No contract file other than the two above needs a change for E1.
